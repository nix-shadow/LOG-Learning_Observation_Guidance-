Scope & Method

This round re-audited the auth/rate-limit seam, OTP lifecycle, JWT claim validation, export sanitization, read-scoping of teacher data, and the frontend offline-sync UX (flush triggers, cache invalidation, honest queued/error/empty states, dead UI). Backend Findings 10 fixed

HIGH · FIXED

B1 — Shared auth rate-limit bucket spanned all auth routes

One limiter covered /api/v1/auth/*: 5 requests/min anywhere (login + OTP + password reset) exhausted the shared bucket; per-route limits were impossible.

  • → backend/internal/handler/middleware.go: newRateLimiter(limit, window) + background cleanupLoop; exported RateLimitLogin=10, RateLimitRequestOTP=5, RateLimitVerifyOTP=20, RateLimitPassword=10, NewLimiter, RateLimitMiddlewareWith.
  • → backend/main.go: per-route limiters on request-otp (5/min), verify-otp (20/min), forgot-password (10/min), google (10/min), login (10/min).
flowchart LR subgraph Before A[client] --> L1[shared bucket 5/min] L1 --> R1[/auth/login/] L1 --> R2[/auth/request-otp/] L1 --> R3[/auth/verify-otp/] end subgraph After C[client] --> L2[login 10/min] C --> L3[request-otp 5/min] C --> L4[verify-otp 20/min] C --> L5[password 10/min] C --> L6[google 10/min] end
HIGH · FIXED

B2 — RequestOTP destroyed the live OTP before verification

Every re-request deleted the previous OTP server-side while the user still held the old code — a second request made verification impossible. No cooldown existed.

  • → backend/internal/service/auth_service_impl.go: sentinel ErrOTPCooldown; only expired/near-expiry records are deleted; the live OTP survives a rejected re-request.
  • → backend/internal/handler/auth_handler.go: ErrOTPCooldown → 429.
  • → Test TestRequestOTPCooldownReturns429: first 200, second 429, live OTP still verifiable after.
HIGH · FIXED

B3 — JWT accepted without exp / jti claims

Middleware validated the signature but tolerated tokens without exp (never-expiring) or jti (un-revocable — the blocklist is keyed by jti).

  • → backend/internal/handler/middleware.go: jwt.WithExpirationRequired(); jti must be present and non-empty, else 401 "Invalid token claims".
  • → LogoutHandler: guards non-numeric exp; audit auth.logout records jti=… (auth_handler.go).
HIGH · FIXED

B4 — CSV export formula injection (spreadsheet malware)

Student names/phones beginning with = + - @ or tab/CR execute as formulas when opened in Excel/Sheets.

  • → backend/internal/handler/export_handler.go: sanitizeCSVCell prefixes '; UTF-8 BOM written so Nepali characters survive Excel; skipped classes counted in the audit detail.
  • → Test TestStudentsCSVExportSanitizesFormulaCells: BOM present, '=SUM(A1:A9) and '+977 sanitized, no raw formula at line start.
HIGH · FIXED

B5 — Teacher reads not scoped to own classes

Assignment/submission reads accepted any moderator ID — an intruder teacher could enumerate another teacher's assignments and learner submissions.

  • → backend/internal/service/learner_service.go + repos: reads scoped via caller teacher_id.
  • → backend/internal/handler/class_handler.go: unenroll of a non-member → 404 (ErrNotEnrolled).
  • → Tests: TestAssignmentReadsScopedToTeacher (intruder 403, owner 200, admin bypass, honest submissions: 0), TestUnenrollNonMemberReturns404.
flowchart LR subgraph Before M1[any moderator] --> Q1[assignment reads] Q1 --> D1[all assignments in DB] end subgraph After M2[teacher] --> Q2[reads scoped by teacher_id] Q2 --> D2[own classes only] M3[intruder teacher] --> Q3[403 Forbidden] end
MEDIUM · FIXED

B6 — Google token validation leaked provider detail

Generic "Invalid Google token" returned; provider detail goes to server logs via slog.Warn (auth_service_impl.go).

MEDIUM · FIXED

B7 — OTP restore resurrected the old role

VerifyOTP un-deleted soft-deleted users but kept the former role. Role now resets to RoleStudent on restore — least privilege (auth_service_impl.go).

MEDIUM · FIXED

B8 — CreateActivity error shape & import hygiene

  • → backend/internal/handler/admin.go: converted to RespondError; errors/gorm imports.
  • → backend/internal/repository/moderator_repo.go: gofmt.
LOW · FIXED

B9 — db.go comment over-claimed FK enforcement

database/db.go now documents the truth: _foreign_keys=on is honored by SQLite, but AutoMigrate creates no FK constraints (models declare no association tags) — referential integrity is enforced at the service layer.

MEDIUM · FIXED

B10 — Roster tests still asserted the pre-fix fabricated roster

Three tests (global roster, needs-attention, constant query count) failed against the caller-scoped model. Stubbed c.Set("userID","mod-1"); needs-attention cross-check scoped to the teacher's classes; seed students enroll into cls-1 with cleanup (handlers_test.go, roster_test.go).

Frontend Findings 17 fixed

HIGH · FIXED

F1 — Sync queue only flushed on the window online event

A user who re-logged-in after expiry (or imported a .logsync file) had no path to flush the queue until the next connectivity event.

  • → src/lib/api.ts: boot window 'load' flush; exported flushSyncQueue() → {synced, failed}.
  • → src/app/login/page.tsx: flush after login/register/Google auth — queued work from an expired session replays with the fresh token (AGENTS.md replay semantics).
  • → src/app/dashboard/page.tsx: sneaker-net import flushes immediately and reports N actions synced.
  • → src/components/SyncIsland.tsx: tap-to-sync with spin state + aria-label.
  • → src/components/CommandPalette.tsx: "Force Data Sync" actually flushes with toasts.
flowchart LR subgraph Before E1[offline] --> E2[queue fills] E2 -. waits .-> E3[window online event only] end subgraph After S1[queue fills] --> S2[flush triggers] S2 --> S3[window load] S2 --> S4[login success] S2 --> S5[.logsync import] S2 --> S6[SyncIsland tap] S2 --> S7[CommandPalette force] end
HIGH · FIXED

F2 — Auth requests were queued to IndexedDB in plaintext

Offline /auth/login attempts stored raw passwords/OTPs in sync-queue. queueRequest now rejects /auth/* with an HttpError, and legacy queued auth entries are dropped on flush (defense in depth) — src/lib/api.ts.

HIGH · FIXED

F4 — Mutating requests never invalidated the GET cache

After a submit/completion, dashboards could serve 24h-stale cache. invalidateRelatedCache now clears /dashboard, /learning-journey, /chart-data for completions and /sync/bulk; submissions clear /assignments; any class/enroll/announcement/assignment/user/role mutation clears the whole API cache (clearApiCache, exported) — src/lib/api.ts.

MEDIUM · FIXED

F5 — "Log out all devices" left the local cache behind

src/app/settings/page.tsx now awaits clearApiCache() before completing the action — a shared school device no longer hands the next user another account's cached dashboards.

HIGH · FIXED

F6 — 401s left the user half-logged-in

Any 401 from fetchWithCache now calls the exported clearCredentialsAndRedirect() — removes log_token/log_user, clears the cookie, redirects to /login — and throws an HttpError. The expired-token path uses the same helper so both routes stay consistent (src/lib/api.ts).

MEDIUM · FIXED

F7 — No submitting state on create/enroll/publish — double-POST risk

  • → AssignmentManager (isCreating), ClassManager (isCreating/isEnrolling), AnnouncementComposer (isPublishing): buttons disable + Loader2 spinner during flight.
  • → Dashboard submit button already disabled via disabled:opacity-40.
MEDIUM · FIXED

F8 — Queued offline writes claimed success as if committed

When the offline layer returns the optimistic 202 {queued: true}, toasts now say "saved offline · will sync when back online" instead of "created/published/submitted" — in AssignmentManager, ClassManager, AnnouncementComposer, and the dashboard submission form.

MEDIUM · FIXED

F9 — Command palette routed to a dead page and faked a sync

/learning-journey → /learning; dead "Profile Settings" entry removed; "Force Data Sync" now calls flushSyncQueue with honest toasts (src/components/CommandPalette.tsx).

MEDIUM · FIXED

F10 — AssignmentManager stale-response race on rapid edits

A requestSeq ref now discards out-of-order responses so the form never overwrites the newest submission list with an older one (src/components/moderator/AssignmentManager.tsx).

HIGH · FIXED

F11/F14 — Lesson page rendered fabricated demo content + fake completion

The entire lessonContent demo, confetti, and demo renderer were deleted from src/app/learning/[id]/page.tsx. The page now shows honest states only:

  • → load error: "Could not load this lesson" + Try Again (reload) — a failed fetch is not an empty state.
  • → empty: "Lesson content is not ready yet" + back to /learning — real, un-fabricated zero state.
  • → Completion rendering is delegated to MicroModuleViewer, which owns the real server-acknowledged completion flow.

Backlog Candidates documented, not implemented

Deliberately deferred — each needs a design decision, a cross-cutting refactor, or product input.

DESIGN

C1 — Audit-log pagination

Audit entries grow unbounded; the admin table loads everything. Needs a page/cursor API + UI before data volumes matter.

REFACTOR

C2 — Unify completion logic

completion_repo.go and sync_repo.go both implement best-score completion; tests pin current behavior. Consolidate into one seam so the two paths can never drift.

ARCHITECTURE

C3 — admin.go service seam

Admin handlers still reach into repositories directly; mirror the SchoolHandler pattern (struct + constructor + actor/audit) for testability.

DATA MODEL

C4 — Real FK constraints

Gorm association tags would let AutoMigrate emit real FOREIGN KEY constraints; today integrity lives at the service layer (documented in db.go).

HONESTY

C5 — Backend Course.Enrolled seed data

Field remains in the model/seed; either compute it from class_members or drop it from the API so the fiction cannot resurface.

CARRYOVER

C6 — Brand contrast (teal/amber ≈ 2:1)

White-on-brand colors fail WCAG AA; needs token-level palette work. Also: recharts dynamic import, per-page retry polish, shared PageState component.
