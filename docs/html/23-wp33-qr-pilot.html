wp33t01 ✓

Poster QR program

AC: partner schools get posters; scanning warms the local cache (offline demo kit)

What was implemented

  • • Admin PilotPosters panel renders a printable QR per activity (qrcode lib, bundled offline) pointing at /qr/<activityId> on the serving origin — school-LAN deployments print correct URLs.
  • • /qr/[activityId] landing records the scan (fire-and-forget), then warms /activities/:id/modules + /learning-journey through fetchWithCache — the scanned lesson works with no signal.
  • • Honest offline copy: when the scan POST fails (offline), the page says the scan is not counted — it never invents a scan.

Proof

  • • frontend/src/app/qr/[activityId]/page.tsx + components/admin/PilotPosters.tsx.
  • • QRLanding.test.tsx — 3 tests: record+warm, mark-started on click-through, honest offline state.
wp33t02 ✓

Pilot measurement

AC: pilot records scans, installs and first-session drop-off; honest report published

What was implemented

  • • PilotScan {poster_id, source, started, created_at} — deliberately no IP/device/user columns (privacy by design, AGENTS.md §3b).
  • • Public POST /api/v1/pilot/scans + /scans/:id/start (rate-limited 30/IP); unknown poster → 404; admin GET /admin/pilot/stats returns scans, 24h scans, starts, distinct posters, start rate and per-poster breakdown — all derived from real rows, honest zeros when empty.
  • • Admin panel renders the numbers; the start-rate is scans-vs-click-throughs, i.e. the pilot's first-session drop-off signal.

Proof

  • • backend/internal/handler/wp33_test.go — 4 tests incl. TestPilotStatsHonestZeros.
  • • PilotPosters.test.tsx — 4 tests: real numbers, honest zeros, load failure, refresh.
