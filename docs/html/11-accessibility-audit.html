Keyboard & focus targets (WCAG 2.4.11 / 2.5.8)

AC: every interactive control has a 44px target and a visible focus ring; verified by tab-through checklist. Implemented globally in globals.css — no per-component drift possible:

  • • Visible focus: :focus-visible gets a 3px neon outline + 2px offset + radius on all interactive elements (links, buttons, inputs, selects, textareas, summaries, roles, tabindex). Existing focus:ring-* button styles remain as a second indicator.
  • • 44px targets: global min-height: 44px on buttons, text inputs, selects, textareas; min-width: 44px on buttons and [role="button"].
  • • Documented exceptions (WCAG 2.5.8 allows): inline text links (Login/Register links, footer links) stay natural size; native checkbox/radio; disabled controls; the Google sign-in iframe button (user-agent control).

wp03t03 ✓

Reduced-motion support (WCAG 2.3.3)

AC: framer-motion variants honor prefers-reduced-motion. Three layers:

  • • framer-motion: <MotionConfig reducedMotion="user"> wraps the whole app in layout.tsx — every motion.* variant (Navigation, SyncIsland, InstallPrompt, SkeletonLoader, MicroModuleViewer, login, forgot-password, PageTransition) auto-reduces. PageTransition additionally uses useReducedMotion() to zero the y-offset.
  • • GSAP: new helper src/lib/motion.ts → prefersReducedMotion() guards all 9 enter animations (home, dashboard, learning, courses, guidance, observation, settings, admin, moderator) — animation is skipped entirely when the user requests reduce.
  • • CSS: a @media (prefers-reduced-motion: reduce) block neutralizes all CSS animations/transitions (shimmer, gradient-x, pulse-glow, spin, view-transition crossfades) and forces scroll-behavior: auto.
  • • The ThreeBackground canvas already self-disables at reduce (pre-existing, verified).

Round 2

Follow-up round (2026-08-19) — dialog semantics, honest surfaces, deeper bundle cuts

The sweep re-checked every component flagged in the audit sheet. Five a11y gaps and five bundle wins, all shipped:

Accessibility

  • • Command palette is a real dialog now. Was ⌘K-only (keyboard-only trigger) with a bare overlay. Now: role="dialog" + aria-modal + label, Tab focus trap, ESC close, focus returns to the trigger (2.4.3), and a visible pointer trigger button (fixed bottom-right, 44px) so mouse-only users can open it. F9 dead entry removed; /learning-journey route corrected to /learning.
  • • SyncIsland: clickable pill ≠ live region. role="status" moved off the clickable element onto a wrapper; the inner element is a real <button> with a label and disabled state during flush.
  • • InstallPrompt: named dismiss + iOS flow. Dismiss button gained aria-label; iOS Safari never fires beforeinstallprompt, so the prompt now detects iOS and shows the honest "Share → Add to Home Screen" instructions instead of silently never appearing.
  • • Chart labels were below AA. recharts ticks used rgba(255,255,255,0.4) ≈ 3.8 : 1 — now var(--brand-muted) (9.2 : 1). Each chart carries a <title> for AT, and animations disable under reduced motion (useReducedMotion + isAnimationActive={false}).
  • • Language + toast + focus-obscuring: Devanagari notice/input now carry lang="ne" (screen readers switch voice correctly); toast pause-on-hover verified as built into react-hot-toast 2.6.0's Toaster (container onMouseEnter/Leave) and documented — no prop exists, so none is added; scroll-padding-top/bottom: 7rem on html so fixed header/footer never obscure focused content (WCAG 2.4.11).

Bundle

  • • Framer-motion features off the critical path: LazyMotion + domAnimation wrap the app; all 9 component/page sites migrated from motion.* to m.* (identical API, features resolve on demand). MotionConfig + reduced-motion behavior unchanged.
  • • CommandPalette + OAuth now load per-use: palette (cmdk + lucide) is next/dynamic, rendered only on first open; GoogleOAuthProvider (Google script + @react-oauth/google) moved out of the root layout into the login page — the whole payload leaves every other route.
  • • three.js only on capable devices: existing CPU/pointer/reduced-motion gates extended with navigator.saveData and effectiveType (2g/3g) checks; the canvas frameloop pauses via frameloop="never" when the tab is hidden — no 60fps battery burn in a background tab.
  • • Service-worker rule pruning: 3 dead runtime rules removed from next.config.mjs (google-fonts ×2 — Inter is build-time self-hosted — and the /next/image rule, dead under unoptimized: true). Every removed rule is one less regex the SW evaluates on each request.
  • • Honest offline page: navigateFallback: "/~offline" + a static ~offline route — offline navigation no longer lands on the browser's dead network error; the page states what happened and offers the Dashboard (which does work offline via cache).
Round 3

Enforcement round (2026-08-19) — keyboard-first nav, announced results

The "max" pass on WP-0.3 — the two gaps the audit sheet left open: no way to bypass the nav with a keyboard, and a command palette whose filtering was silent to AT users.

  • • Skip-to-content link (WCAG 2.4.1). A visually-hidden link in the root layout surfaces on keyboard focus — "Skip to content" jumps past the fixed nav to <main id="main-content" tabIndex="-1">, which receives focus on activation (focus is moved, not just scrolled).
  • • CommandPalette trigger linked to the dialog (WCAG 4.1.2). The open button now declares aria-haspopup="dialog" + aria-expanded, so AT announces the relationship and state of the thing the button controls.
  • • Palette results announced (WCAG 4.1.3). cmdk narrows the list as you type with no announcement — a screen-reader user hears silence. A polite role="status" live region mirrors the visible-item count ("3 results." / "No results found.") via a MutationObserver over [cmdk-item] visibility.
  • • Honesty carried into the report itself: the Round-2 bullet about pauseOnHover corrected — react-hot-toast 2.6.0 has no such prop; pause-on-hover is built into the Toaster container, so the code documents instead of pretending.
