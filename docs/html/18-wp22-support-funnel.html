wp22t01 ✓

Structured support funnel

AC: issue wizard → guidance article → community → admin escalation, in NP and EN.

What was implemented

  • • /support wizard: category (device/connectivity/account/content/other) → bilingual guidance (real local copy, never invented help) → "did this help?" → describe + escalate → done.
  • • POST /support/issue (rate-limited 10/IP) records the SupportIssue; GET /support/my-issues lists the reporter’s own issues with honest empty state.

Proof

  • • wp22_test.go TestSupportIssueCreate + TestSupportEscalation; support/page.tsx wizard; EN+NP guide copy.
wp22t02 ✓

Moderator resolution inbox

AC: escalated issues land in an admin/moderator inbox; every action audit-logged.

What was implemented

  • • GET /support/inbox returns open escalated issues only (moderator/admin); PUT /support/issue/:id resolves with a required resolution_note.
  • • SupportInbox component mounted on /moderator and /admin; SupportIssue events audit-logged.

Proof

  • • wp22_test.go TestSupportInboxModeratorOnly + TestSupportResolve; SupportInbox.test.tsx (3 tests).
