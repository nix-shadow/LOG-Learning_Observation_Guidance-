wp43t01 ✓

Metrics registry & 5xx alarm

AC: registry counts request outcomes without PII; a 5xx spike alarms once per episode

What was implemented

  • • backend/internal/metrics/metrics.go — per-route-pattern counters keyed by c.FullPath() (pattern, never user ids): keys cannot carry PII by construction.
  • • Middleware records every request (unmatched 404s recorded with the empty pattern, kept out of render); spike alarm fires at ≥5 5xx within a 60s sliding window, once per episode, re-arming only when the window empties — no alert storms.
  • • Public GET /metrics serves Prometheus-style text; admin GET /api/v1/admin/metrics serves JSON snapshot. Uptime is honest: a server up 3 seconds says 3, not 0.

Proof

  • • backend/internal/metrics/wp43_test.go — pattern recording, spike fires once and re-arms, render never contains user ids, uptime honesty.
wp43t02 ✓

Opt-in analytics consent

AC: analytics tracking is opt-in, withdrawable, and the admin summary only counts opted-in learners

What was implemented

  • • analytics consent type (policy 2026-08-v1) with a real withdrawal path: POST /me/consent accepts status: granted|withdrawn — withdrawal sets WithdrawnAt and writes a privacy.consent_withdrawn audit row (vs privacy.consent_granted).
  • • Settings toggle is three-state (null | true | false) — "not loaded yet" is never shown as "opted out"; switch is accessible (role="switch" + aria-checked).
  • • GET /api/v1/admin/analytics/summary is aggregate-only, computed exclusively over opted-in learners (consent_records WHERE consent_type='analytics' AND status='granted'); avg_score is null when there is no opted-in completion — a fabricated 0 is impossible.

Proof

  • • backend/internal/handler/admin_test.go — TestAnalyticsSummaryOptInGate (opted-out completions excluded, null avg never fabricated), TestAnalyticsConsentWithdrawal, TestAnalyticsSummaryDelegatesAndIsNeverFabricated.
  • • Frontend: frontend/src/app/settings/page.tsx toggle; privacy pack doc §10.7 "Round 4 — opt-in analytics".
