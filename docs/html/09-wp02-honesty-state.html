WP-0.2 — Honesty & State Hygiene

The shipped record for the WP-0.2 work package (tracker tasks wp02t01–wp02t04): real server-persisted enrollment state, paginated audit logs, an executable honesty guarantee for the "no invented numbers" rule, and regression tests locking in the offline queue's integrity. Every acceptance criterion maps to code, a test, or a measured check below.

wp02t01 ✓

Persist real enrollment state (C5)

AC: per-learner Course.Enrolled state persisted server-side; dashboard goal ring and catalog derive every number from real data. Before WP-0.2, enrolled counts were static seed integers — a fabricated number. Now every number derives from real rows.

Backend

  • • New Enrollment model (domain.go, auto-migrated in db.go) with uniqueIndex:uq_enrollment on (user, course) — one row per learner per course, no duplicates possible.
  • • Course.IsEnrolled bool gorm:"-" — a per-caller annotation, never a stored column.
  • • Endpoints POST/DELETE /api/v1/courses/:id/enroll (learner_handler.go): idempotent both ways, 404 on unknown course, and the create is race-safe — a unique-index conflict on the insert falls back to "already enrolled" (two tabs enrolling at once cannot double-book).
  • • Catalog counts now derive from the real table: UPDATE courses SET enrolled = (SELECT COUNT(*) FROM enrollments …) runs at every startup (so legacy static seed values are corrected), and the catalog query counts the caller's own rows for IsEnrolled (course_repo.go).
  • • Demo learner seed: user-123 enrolled in course-1 and course-3 — the catalog/dashboard numbers shown to the demo user are real rows, not literals.

Frontend

  • • Catalog cards (src/app/courses/page.tsx) render an "Enrolled ✓" toggle backed by the new endpoints, with live counts from the API.
  • • Offline behavior stays honest: an enrollment click while offline goes through the sync queue and shows "will sync" — never a fake success.
  • • invalidateRelatedCache (F4) treats /enroll as low-frequency and clears the whole cache, so a synced enrollment is reflected everywhere.

Audit-log pagination (C1)

AC: audit-log listing is paginated; no unbounded row load; page size configurable.

  • • GET /api/v1/audit-logs (audit_handler.go) now accepts limit (default 50, max 200) and offset (default 0), and returns total alongside entries for page-count math — never an unbounded row load.
  • • Invalid values fall back to defaults; the cap (200) keeps any single request bounded.
  • • Regression test TestAuditLogPagination walks pages and proves no rows are skipped or duplicated across page boundaries.

Honest-zero sweep

AC: goal ring, moderator roster and chart-data empty states audited — every component shows honest 0/empty state; a unit test asserts no placeholder stubs exist.

  • • src/app/observation/page.tsx: progress fields that rendered undefined when the API had no data now render ?? 0; the two charts show honest empty-state overlays ("No activity data yet — your progress chart appears here after your first completed activity") instead of blank canvases.

wp02t04 ✓

Queue-integrity regression tests

AC: Jest suite covers: 401 retains queue, token re-attach at flush, cache invalidation after /complete and /sync/bulk. Three new tests in __tests__/api.test.ts, exercising the encrypted WP-0.1 queue end-to-end:

  • • 401 retains queue — a flush that hits a 401 (expired session) keeps every queued record; the flush stops and the user must re-login. Deleting would lose learner work, so the test asserts nothing is removed.
  • • Token re-attach at flush — records queued under an expired session sync after re-login because the flush re-attaches the current token from localStorage at replay time; the test simulates login-after-queue and asserts the replayed request carries the fresh token.
  • • Cache invalidation after /sync/bulk — a successful bulk sync clears the /dashboard, /learning-journey and /chart-data cache entries (the completion path already invalidates via /activities/:id/complete; this closes the sneakernet/import path).
Round 2

Follow-up round (2026-08-19) — four honesty gaps closed

The research sweep re-read every number-producing path. Four gaps surfaced; all four shipped with tests.

  • 1 · Fabricated "zero week" deleted. GetChartData used to synthesize a 7-day window of zeros when a learner had no activity — an invented series (AGENTS.md §1 violation) that also faked the chart's x-axis. It now returns an empty slice; the frontend empty state renders instead. Locked by TestGetChartDataHonestEmpty + TestGetChartDataOnlyRealRows.
  • 2 · Completion timestamps are honest. The backend used to stamp completions with server time — fine online, but offline completions (queued, flushed later) got the flush time, not the learner's completion time, corrupting streak/day analytics. POST /activities/:id/complete now accepts completed_at_unix_ms + timezone_iana from the client; the backend clamps into [now−14d, now+24h] (a device with a broken clock cannot rewrite history), falls back to server-now on garbage, and computes the learner-local calendar date for DailyActivity rows. Tests: TestAttemptStatsCompletedAtHonestClamp (4 cases), TestCompleteActivityUsesClientTimestamp, TestSyncBulkTimestampParity.
  • 3 · Enrollment toggle stops lying on errors. courses/page.tsx used .catch(() => null) — a failed request left the UI flipped while the server state never changed. Now the state flips only on success or queue-acceptance; 4xx shows "Enrollment not changed: …" and leaves the card untouched.
  • 4 · Honesty scanner now guards the backend too. backend/internal/honesty/honesty_test.go walks all Go sources (excluding _test.go and vendor) and fails on fabricated-pattern identifiers and rand-based scores — the mirror of the TS scanner. Runtime-built pattern strings ("Mon" concatenated) keep the scanner from matching itself.
Round 3

Enforcement round (2026-08-19) — freshness markers & scanner hardening

The "max" pass on WP-0.2: data is honest, now it must also be visibly fresh — and the honesty guarantee itself gets stronger.

  • 1 · as_of freshness marker shipped. GET /dashboard and GET /chart-data now include the server-clock as_of timestamp. The dashboard hero and the Observation charts render "Updated <date> at <time>" from it — a cached payload (24h TTL) can no longer masquerade as live data; staleness is visible, not hidden. The chart label is a polite live region (aria-live).
  • 2 · Go scanner now catches week-builder and date-window fabrication. Two new runtime-assembled patterns: a hardcoded weekday-name slice ("Mon","Tue","Wed" — the tell-tale of any future weekly-series fabrication) and a hardcoded absolute year inside time.Date(2XXX, (a fabricated analytics window pinned to a fixed date). Verified clean against the full source tree.
  • 3 · Frontend queue 403 handling (consent boundary, honesty of sync). The queue now distinguishes consent_required 403s from generic 4xx: records are preserved and the flush stops with a "grant consent in Settings" toast — a consent-gated rejection is never treated as a terminal delete (that would silently drop offline learner work).
