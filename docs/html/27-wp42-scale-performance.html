wp42t01 ✓

Pool sizing & index set

AC: GORM pool sized for single-writer SQLite; index choices benchmarked, not assumed

What was implemented

  • • db.go: SetMaxOpenConns(1) / SetMaxIdleConns(1) / SetConnMaxLifetime(0) — one writer, no SQLITE_BUSY churn, documented in docs/QUERY_PLANS.md.
  • • idx_da_learner_date composite (daily_activities learner_id, date) kept — SEARCH evidence; idx_ann_created_at added to announcements — kills the USE TEMP B-TREE FOR ORDER BY (the only temp-b-tree left on the hot list).
  • • A completed_at index on learner_activities was built, benchmarked to 200k rows (with/without ANALYZE), and rejected: the planner kept the PK scan and runtime was identical (18.806 ms vs 18.825 ms). The rejection is documented in domain.go as a NOTE and in QUERY_PLANS.md — no index that doesn't move the plan.

Proof

  • • docs/QUERY_PLANS.md — real EXPLAIN QUERY PLAN for 10 hot queries, the studied-and-rejected indexes, and re-run instructions.

Budget checker

AC: CI fails when any route exceeds the 500 kB budget

What was implemented

  • • frontend/scripts/check-budget.mjs — runs npm run build (or takes a --file log) and parses the real route table; exit 1 on offenders, 2 on invalid input / no route table. No route table parsing = no passing grade.
  • • Wired into CI in place of the bare Build step, and as make budget locally.
  • • Current reality: all 15 routes ≤ 174 kB vs the 500 kB budget — honest headroom; the manual real-device TTI < 5s step lives in docs/RELEASE.md because CI cannot measure it.

Proof

  • • node scripts/check-budget.mjs → PASS (max 174 kB, 15 routes).
  • • .github/workflows/ci.yml step "Build + RESPECT budget check (WP-4.2)".
