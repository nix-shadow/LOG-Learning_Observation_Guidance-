Phase A — Critical Bugs (fix first, small diffs)

CRITICAL · VERIFIED

A1 — Cross-account SW cache leak is STILL LIVE (round-1 finding 1.6)

next.config.mjs:6-8 filters the cross-origin catch-all by string, but next-pwa 5.6 defines it as a function (node_modules/next-pwa/cache.js, urlPattern: ({url}) => !isSameOrigin). Verified in the generated public/sw.js: cacheName:"cross-origin", NetworkFirst, maxAgeSeconds:3600 is still registered. Every authenticated GET (dashboard/roster — with Authorization header) is SW-cached by URL only, survives logout → user B inherits user A's data offline on shared school devices.

  • Fix: filter function-based entries whose urlPattern matches !isSameOrigin (or replace runtimeCaching with an explicit same-origin allowlist), then rebuild; add caches.delete('cross-origin') + caches.delete('apis') in logout()/clearCredentialsAndRedirect() as belt-and-braces.
flowchart LR A[User A fetches /dashboard] --> B[SW caches cross-origin response keyed by URL] A2[User A logs out] -. cache survives .-> C B --> C[User B opens app offline] C --> D[B receives A's dashboard data — leak] E[Fix: drop cross-origin catch-all] --> F[SW caches nothing API-related] F --> G[IndexedDB layer owns offline data]
CRITICAL · VERIFIED

A2 — Per-route rate limits are dead code (round-2 fix was incomplete)

backend/internal/handler/middleware.go:62-64 — allow() still uses the package constants rateLimitWindow/rateLimitMax (5/min) instead of rl.window/rl.limit. Every limiter — NewLimiter(RateLimitVerifyOTP=20), RateLimitLogin=10, etc. — actually enforces 5/min, so a class of 30 students still hits the NAT lockout. Any future budget tuning is silently ignored.

  • Fix: use rl.limit/rl.window in allow(); add a unit test asserting NewLimiter(20, time.Minute) admits 20 requests (this exact test would have caught it).
HIGH

A3 — Exported .logsync sneakernet files embed the JWT

syncExport.ts:6-26 dumps raw queue records including headers.Authorization: Bearer <JWT> into a file explicitly carried on USB and handed to a teacher; if the importing device lacks a fresh token, replay falls back to the stored header and syncs as the original student. A stolen USB = a stolen session (up to 24h).

  • Fix: strip headers (and any Authorization) in exportSyncQueue(); validate version === '1.0', per-item shape, and a 5 MB size cap in importSyncFile(); route imports through the same best-score merge as queueRequest.
HIGH · FUNCTIONAL GAP

A4 — OTP is never delivered — "OTP sent" is a mock

Zero SMS/WhatsApp/email gateway exists (auth_service_impl.go:32-64); the code exists only in the DB. Combined with seed users that have real phone numbers and empty password hashes (db.go:90-97), seeded admin/teacher accounts cannot log in at all outside a dev console.

  • Fix: gate delivery behind SMS_PROVIDER env and fail loudly when unset (no fake success); seed bcrypt password hashes for admin/teacher so email login works today; document the limitation in the demo path.

LMS Research — What Others Do & What LOG Should Steal

Full 22-feature matrix + citations in docs/LMS_EDTECH_COMPARISON.md. Highlights:

Kolibri / KA Lite (offline king)

Content packs via USB, LAN peer import, learn-only devices auto-syncing on school Wi-Fi, Pi-as-access-point serving 35 tablets, mobile "school van" model. LOG's .logsync is exactly this pattern — the gap is content-pack distribution and roster provisioning.

Moodle / Canvas (school ops)

Gradebook, competency frameworks, forums, parent/guardian accounts, CSV rosters, badges, completion tracking. LOG covers class/enroll/assign/announce — missing gradebook-level visibility and roster import.

Duolingo (retention)

Streak freezes (17.2 vs 11.6 day streaks), class-scoped leagues of ~30, day-one badges (33.4% vs 20.4% retention), spaced repetition (SM-2). Research warns: rewards decoupled from real progress backfire — LOG's supportive-language principle is the right frame.

What LOG already does better than the majors

No mainstream LMS ships a first-class offline queue with sneakernet sync, optimistic 202 writes, and honest queued-state UX. The recommended roadmap below never trades that away.

Anti-patterns — explicitly do NOT build

✗ Video streaming-first content

Needs progressive download / content packs; Nepal median upload ~14 Mbps, 68.5% internet in Karnali.

✗ Real-time chat / live classes

Dependent on connectivity; async teacher replies to guidance notes work offline.

✗ Cloud-LLM content generation

Violates AGENTS.md No-Hallucinations; keep deterministic server-side guidance.

✗ Global leaderboards

Demotivate on shared devices; class-scoped, streak-based leagues are supportive.

✗ "Occasional cloud call" features

Anything gated on the network silently dies in the classroom; design offline-first.

✗ Monetized gems/energy

Pay-to-continue models have no place in Nepali public schools.
